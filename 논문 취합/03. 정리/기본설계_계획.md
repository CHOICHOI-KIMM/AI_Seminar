## 2. 드라이브트레인 설계 분석/평가 및 보강 제안

### 2.1 전체 평가

전반적으로 설계조건 정의가 상당히 포괄적이며, 특히 설계변수와 제약조건을 분리하여 정의한 점, 레퍼런스를 다각도로 확보한 점이 잘 되어 있다. IEA 15/22MW 레퍼런스와 RWTH, Fraunhofer 논문을 병행 참조한 것은 학술적·실무적 균형이 좋다.

### 2.2 보강 필요 항목

#### (1) 하중 정의의 구체화
- 6자유도 하중의 출처를 명확히 해야 한다. IEC 61400-1의 DLC(Design Load Case)별 하중 매트릭스와의 연결이 필요하다.
- 극한하중과 등가피로하중의 출처(에어로 시뮬레이션 결과인지, IEA 레퍼런스에서 스케일링한 값인지)를 명시해야 한다.
- 하중 전달 경로(Hub → Main Shaft → Main Bearing → Bedplate)를 다이어그램으로 정리하면 설계 근거가 명확해진다.

#### (2) 설계평가 기준의 보완
- **좌굴 평가:** 중공축일 경우 D/t 비율이 클 때 국부좌굴 가능성 검토 필요
- **공진 해석:** 캠벨 다이어그램을 통한 고유진동수와 운전 회전수 간섭 확인 필요
- **프레팅 피로:** 베어링 시트 부위의 접촉응력/프레팅 피로 평가 추가 필요
- **크립 평가 명확화:** 일반적인 풍력 운전 온도(−20~+60℃)에서 강재 크립은 이슈가 아님. 베어링 내륜 크립(Inner Ring Creep)을 의미하는 것이라면 별도로 구분하여 기술 필요

#### (3) 인터페이스 정의 강화
- 허브 플랜지 볼트 패턴(PCD, 볼트 수, 등급)
- 기어박스 커플링 방식(슈링크 디스크, 스플라인, 플랜지 등)
- 메인베어링 시트의 기하공차(원통도, 진원도, 표면조도 Ra 값)
- → 초기 설계 단계에서부터 정의되어야 외경과 길이를 결정할 수 있음

#### (4) 소재/열처리 섹션의 구체화
- 후보 소재 명시 필요: 단조축이면 42CrMo4(1.7225), 주조 일체형이면 EN-GJS-400-18 등
- 각 소재별 DIN 743 평가에 필요한 물성값(인장강도, 항복강도, 피로한도, 노치감도계수 등) 정리 필요
- 단조 vs 주조 일체형의 트레이드오프 분석을 초기에 수행할 필요 있음

#### (5) 메인베어링과의 설계 연동
- 실제로는 양방향 반복(iteration)이 필요함
- 베어링 타입(TRB, SRB, CARB 등)에 따라 샤프트 형상이 크게 달라짐
- 베어링 배열(2-point, 3-point suspension)에 따라 하중 분배와 샤프트 길이가 결정됨
- 이 상호의존성을 설계 프로세스에 반영해야 함

## 4. 메인베어링 설계 분석/평가 및 보강 제안

### 4.1 전체 평가

드라이브트레인 대비 메인베어링 쪽이 더 구체적으로 정의되어 있다. 설계변수가 롤러 레벨까지 세분화되어 있고, 윤활 평가 기준도 ISO 281부터 혼합윤활 수치해석까지 계층적으로 구성한 점이 좋다. Rothe Erde 논문 2편은 TRB 메인베어링 설계에 직접적으로 적합한 레퍼런스이다.

### 4.2 보강 필요 항목

#### (1) "5자유도" 표현 정리
- TRB×2 배열은 5자유도(Fx, Fy, Fz, My, Mz)를 구속하고 축방향 회전(Mx, 즉 토크)은 전달하는 구조
- 축방향력(Fa) 방향에 따라 두 베어링 간 하중 분담이 달라지므로, B2B와 F2F 배열에서 각 베어링이 담당하는 하중 조합을 명시적으로 정리 필요

#### (2) 배열 선정 근거 보강
- B2B: 모멘트 강성 높음, 베어링 간격 축소 가능, 열팽창에 민감
- F2F: 모멘트 강성 상대적 낮음, 열팽창에 덜 민감
- 초기 단계에서 정성적 트레이드오프 매트릭스 작성 → Phase 2에서 정량 비교 권장
- 15MW 이상급에서는 열관리 이슈로 재검토 필요 가능

#### (3) 피로 수명 평가 체계 보완
- **aISO 수명 수정계수:** 오염도 계수(eC)와 윤활 조건(κ) 결정 근거 사전 정의 필요. 풍력 메인베어링은 저속·고하중·그리스 윤활이라 κ가 매우 낮음
- **ISO 16281:** 롤러 프로파일(크라우닝)과 내부 틈새/예압이 직접 영향. 자체 도구 vs 상용 소프트웨어(BEARINX, ROMAX 등) 결정 필요
- **SKF GBLM:** SKF 고유 모델이므로 다른 제조사 베어링 적용 시 호환성 이슈. 자체 설계라면 기본 표면 피로 모델 선정 필요

#### (4) 윤활 평가의 단계적 구조화
1. **1차:** ISO 281 기반 κ(점도비) 계산 → 윤활 상태 스크리닝
2. **2차:** EHL(탄성유체윤활) 해석 → 최소 유막두께, Lambda ratio 계산
3. **3차:** 혼합윤활 해석(필요시) → 고체접촉 비율, 마찰 발열 평가
4. **그리스 Starvation:** 운전 초기 vs 장기 운전 구분, 그리스 재보급 주기와 연계

#### (5) 내부 기하학 설계 도구
- 롤러 수 vs 피치원 직경, 접촉각 vs 축방향 하중능력 등 관계식 계산 도구 필요
- 해석적 직접 구현 vs 상용 툴 의존 결정 필요
- 직접 구현 시 ISO/TS 16281 기반 내부 하중 분포 계산 모듈이 핵심

#### (6) 예압 설계 전략
- 운전 중 열팽창에 의한 예압 변화를 반드시 고려 (열해석 또는 열팽창 추정 필요)
- 초기 예압(cold preload)과 운전 예압(hot preload) 구분
- 전체 운전 온도 범위에서 예압이 항상 양(positive)인지, 과도한 예압이 수명을 단축시키지 않는지 확인하는 프로세스 필요

#### (7) 크립(Inner Ring Creep) 평가 누락
- Fraunhofer 논문 제목에 "inner ring creep"이 명시되어 있으나 메인베어링 설계조건에서 이 항목이 빠져 있음
- 대형 TRB 메인베어링에서 내륜 크립은 주요 고장 모드
- 조립 공차(끼워맞춤)와 연계하여 반드시 평가 항목에 추가 필요
- 드라이브트레인 설계의 크립 평가와 연결되는 항목

---

## 5. 통합 단계별 설계 로드맵

### Phase 1: 통합 설계 입력 확정
- 하중 세트 확정 → 드라이브트레인과 메인베어링에 동일 하중 기준 적용
- TRB×2 배열(B2B vs F2F) 정성적 비교 → 1차 선정
- 소재 후보군 정리: 샤프트(42CrMo4 등), 베어링(100Cr6, 표면경화강 등)

### Phase 2: 1D 연동 설계
- Timoshenko 빔 모델로 샤프트 모델링, 베어링을 스프링 요소로 치환
- 베어링 간격(L)과 샤프트 외경을 동시에 변화시키며 평가:
  - 베어링 시트 기울기
  - 베어링 하중 분담
  - 샤프트 강도
- ISO 281/76 기반 베어링 수명/정적 안전율 스크리닝
- 파라메트릭 스터디로 최적 설계 영역 축소

### Phase 3: 베어링 내부 설계
- Phase 2 결과 기반 베어링 외형 치수(D, d, T) 확정
- 내부 기하학 설계: 롤러 수, 크기, 프로파일, 접촉각
- ISO 16281 기반 내부 하중 분포 해석
- 롤러 프로파일 최적화(에지 응력 최소화)
- 윤활 평가(κ, Lambda, EHL)

### Phase 4: 3D FEA 상호 검증
- 샤프트 + 베어링 통합 FEA 모델 구성
- 베어링 시트 접촉 해석, 내륜 크립 평가
- 응력집중부 상세 해석
- 모달 해석 → 시스템 고유진동수 확인

### Phase 5: 열해석 및 예압 검증
- 운전 조건별 온도 분포 추정
- 열팽창에 의한 예압 변화 계산
- 전 운전 범위에서 예압 적정 범위 확인

### Phase 6: 제조성·조립성 최종 검토
- 끼워맞춤 공차, 표면 처리, 열처리 조건 최종 확정
- 공차 스택업 분석 수행

### 7.2 다이어그램 1 — 통합 설계 프로세스 플로우차트

**레이아웃:** Dual-Track Convergence Flow — Phase 1·5·6은 단일 트랙, Phase 2~4는 Shaft/Bearing 병렬 트랙 + 반복 루프

> **핵심:** Phase 2~4 사이의 반복 루프가 설계의 핵심 과정이며, 샤프트와 베어링이 상호 수렴할 때까지 반복. 6장 보완사항 참조.

| | Shaft Track | Bearing Track |

| | Shaft Track | Bearing Track |

| 캠벨 다이어그램 간섭 | Ph4 말 | **Ph2** | Shaft 강성 변경 (OD, 두께, 길이) |

**역방향 전달 데이터:**
- Phase 4 → 2: 수정 필요 항목 + 정량 근거 (예: "Fillet 2→5mm, 응력 1.8배 초과")
- Phase 3 → 2: 외형 치수 변경 요청 + 근거 (예: "d ↑ 필요, 프로파일만으로 에지 응력 해소 불가")

### 7.3 다이어그램 2 — 설계조건 체계도

**구조:** 3열 레이아웃

| Main Shaft (좌측) | Shared Inputs (중앙) | Main Bearing (우측) |
|-------------------|---------------------|---------------------|

**7개 행(카테고리):**

1. **Function:** Hub support / Gearbox torque ↔ Load path coupling ↔ Shaft support / 5-DOF absorption
2. **Performance:** Static/fatigue/deflection ↔ Manufacturability ↔ Static safety/rolling fatigue/lubrication
3. **Operating conditions:** 6-DOF loads (hub) ↔ RPM, cycles, temp, DLC ↔ Fr, Fa per bearing / misalignment
4. **Evaluation criteria:** DIN 743 / Timoshenko / FEM ↔ (독립) ↔ ISO 76/281/16281 / GBLM / EHL
5. **Design variables:** OD, thickness, taper ↔ Bearing seat OD = d ↔ D, d, Dpw, profile, preload
6. **Material/HT:** 42CrMo4 / Q&T ↔ (독립) ↔ 100Cr6 / case-harden
7. **Assembly:** Hub bolt pattern / GB coupling ↔ Interference fit / creep ↔ Shaft seat / housing tolerance

**핵심 상호의존성 (하단 강조):**
- Shaft OD at bearing seat = Bearing bore (d) → 기하학적 연동
- Shaft deflection → bearing misalignment → life reduction
- Interference fit → inner ring creep risk → assembly tolerance

### 7.4 다이어그램 3 — 하중 전달 경로도

**구조:** 상단 — 드라이브트레인 단면 스케치, 하단 — 인터페이스별 하중 성분

**단면 스케치 요소:**
- Wind loads (외부 입력, 6 DOF) → Hub flange
- Main shaft (42CrMo4, hollow, taper profile)
- TRB #1 (rotor-side), TRB #2 (generator-side) — 상하 대칭 배치
- Bedplate / housing (상하)
- Gearbox coupling → Mx (torque) 출력
- Bearing span L 치수선

**인터페이스별 하중 성분:**

| Hub Interface | Bearing Loads | Gearbox Input |
|--------------|---------------|---------------|
| Fx, Fy, Fz, Mx, My, Mz | Fr, Fa per bearing, Misalignment | Mx (torque only), Reaction loads |
| (6 DOF) | (5 DOF absorbed) | (1 DOF transfer) |

**핵심 커플링:** bearing span L ↔ shaft deflection ↔ bearing misalignment

## 8. 다이어그램 유지관리 플랫폼 검토

### 8.1 핵심 요구사항

### 8.2 검토 방안 비교

#### 방안 1: Markdown + Mermaid.js
- **방식:** `.md` 파일 내 Mermaid 코드 블록으로 다이어그램 정의, GitHub/VS Code/Obsidian에서 렌더링
- **장점:** 진입 장벽 최저, 별도 서버 불필요, Git 버전 관리
- **단점:** 복잡한 레이아웃(매트릭스, 단면 스케치) 표현 한계, 스타일 커스터마이징 제한
- **적합 다이어그램:** 1(플로우차트), 5(트레이서빌리티) — 7장 참조
- **부적합:** 3(단면도), 4(매트릭스 히트맵)

#### 방안 2: YAML/JSON 데이터 + Python 렌더링 (Matplotlib/Plotly)
- **방식:** 설계 데이터를 YAML로 구조화, Python 스크립트가 읽어서 다이어그램 자동 생성
- **장점:** 데이터-렌더링 완전 분리, YAML 수정만으로 자동 갱신, Python 생태계 풍부, Jupyter 통합 가능
- **단점:** 초기 스크립트 작성 필요, 비개발자 환경 셋업 번거로움
- **적합 다이어그램:** 전체 (1~5 모두 커버 가능)

#### 방안 3: Markdown/JSON + D3.js/React 웹 대시보드
- **방식:** 데이터 파일을 웹 프론트엔드가 읽어서 인터랙티브 다이어그램 렌더링
- **장점:** 인터랙티브 기능 최고, 브라우저 접근 가능, 실시간 협업 적합
- **단점:** 프론트엔드 개발 역량 필요, 초기 구축 비용 최고
- **적합 시점:** 팀 규모 확대 또는 외부 공유 필요 시

#### 방안 4: Obsidian + Dataview + Mermaid
- **방식:** 각 설계 항목을 개별 노트로 작성, YAML 프론트매터에 메타데이터, Dataview가 테이블 자동 생성
- **장점:** 지식 관리 + 다이어그램 통합, 그래프 뷰로 관계 탐색, 로컬 파일 기반
- **단점:** Obsidian 종속, 복잡한 다이어그램 한계, 팀 전원 Obsidian 사용 필요

#### 방안 5: YAML + Python + Streamlit 웹앱
- **방식:** 방안 2에 Streamlit 래퍼 추가, 로컬/사내 서버에서 웹 대시보드 제공
- **장점:** Python 유연성 유지 + 비개발자 브라우저 접근, 인터랙티브 위젯, 학습 곡선 낮음
